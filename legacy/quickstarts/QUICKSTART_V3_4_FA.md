# راهنمای Wallex Atlas V3.4 — Context Engineering

**وضعیت:** فقط Research و Shadow؛ **بدون خرید، فروش یا برداشت واقعی**؛ هیچ داده مصنوعی در کد یا تست‌های نسخه جدید.

## نصب روی نسخه فعلی V3.3

پچ را در ریشه پوشه `D:/Hackaton/Wallex/wallex_agent_v3` استخراج کنید و فایل‌های هم‌نام سورس را جایگزین کنید. `atlas_store` را حذف یا جابه‌جا نکنید.

اگر `python -m wallex_bot.atlas_cli watch --hours 48` همچنان در حال اجراست، پس از یک چرخه ثبت‌شده از `Ctrl+C` استفاده کنید و **بعد** پچ را نصب کنید. پچ فایل Session را حذف نمی‌کند و اجرای مجدد از زمان شروع ذخیره‌شده ادامه می‌یابد. فاصله‌ای که فرایند خاموش بوده با مشاهده یا قیمت فرضی بازسازی نمی‌شود.

در Git Bash و محیط `shbk`:

```bash
cd /d/Hackaton/Wallex/wallex_agent_v3
conda activate shbk
bash run_v3_4.sh
```

این اسکریپت فقط تست‌ها، وضعیت حافظه و Lessonها را نشان می‌دهد؛ خودکار یک `watch` دوم راه‌اندازی نمی‌کند.

سپس برای ادامه همان مشاهده آینده‌نگر قبلی:

```bash
python -m wallex_bot.atlas_cli watch --hours 48
```

## دستورات جدید بدون پارامتر قابل جایگزینی

```bash
python -m wallex_bot.atlas_cli context-status
python -m wallex_bot.atlas_cli context-preview
python -m wallex_bot.atlas_cli context-review
python -m wallex_bot.atlas_cli contest-readiness
```

- `context-status`: شمارش رویدادهای پایدار، اعتبار hash chain، درس‌های بالقوه.
- `context-preview`: نمایش کانتکست کوتاه و مهارت‌های انتخاب‌شده برای Watch؛ محتوای خام خبرها وارد کانتکست نمی‌شود.
- `context-review`: فرضیه‌های تأییدنشده و بدون حق تغییر سیاست یا مدل.
- `contest-readiness`: بخش `context_engineering` و بدهی‌های باقی‌مانده را نشان می‌دهد.

## سازوکار حافظه

- **Working Context:** نمای حداکثر حدود ۱۸۰۰ توکنِ تخمینی؛ متن در هر اجرای پردازشی از حافظه و Skillهای محلی ساخته می‌شود.
- **Episodic:** SQLite `atlas_store/context_memory.sqlite` برای چرخه‌ها، رویدادهای Agent و خطاها؛ append-only با اتصال SHA-256.
- **Procedural:** دستورالعمل‌های کنترل‌شده در `atlas_skills/` که فقط برای فاز مرتبط باز می‌شوند.
- **Semantic candidate:** درس‌های مبتنی بر رویداد، به شکل `CANDIDATE` ذخیره می‌شوند. ارتقای هر درس به شواهد مستقل نیاز دارد و هیچ مدل معاملاتی را خودکار تغییر نمی‌دهد.

فایل‌های ریشه‌ای حسابرسی بازار و مدل اصلی باقی می‌مانند؛ «پاکسازی کانتکست» حذف تاریخچه معتبر نیست.

## حفاظت در برابر Prompt Injection

متن GDELT/RSS یا پاسخ ابزار، هیچ حق دسترسی تازه‌ای دریافت نمی‌کند. خبرها فقط داده ساخت‌یافته و زمان‌دارند. `news_known_at` همچنان قانون مشاهده قبل از پیش‌بینی را حفظ می‌کند. دستورهایی مانند `ignore risk` اگر داخل متن خبر ظاهر شوند، دستور سیستم یا مجوز معامله محسوب نخواهند شد.

## محدودیت

پیاده‌سازی رجیستری و Skillهای ایستا، یادگیری خودکار سودآور یا استفاده از LLM سنگین را اثبات نمی‌کند. هنوز باید نتیجه آزمون واقعی ۴۸ساعته را روی `forward_observations.sqlite` دید. ابزار معاملات واقعی موجود نیست و ممنوعیت بازارهای غیرمجاز همچنان برقرار است.
