## ۲. Broker، حساب و موانع واقعی

`RealSpotBroker` اکنون پیش‌بررسی دقیق Decimal برای LIMIT، کنترل Tick/Step و
حداقل‌های صریح، RiskGate، هویت پایدار Client ID، زنجیرهٔ ممیزی، اجرای تجمعی،
کارمزد تفکیک‌شده برحسب دارایی و Reconciliation خواندنی دارد. Crash در حالت
ارسال/لغو در انتظار به UNKNOWN تبدیل می‌شود؛ تکرار خودکار وجود ندارد.
ابهام `FINISHED/FILLED` در مستندات با فرض Fill حل نشده است.

**آنچه هنوز پیاده یا تأیید نشده:** POST/DELETE مالیِ قابل بهره‌برداری، ARM
محلی اپراتور، مسیریابی تأییدشدهٔ حساب اختصاصی، تطبیق اقتصادی موجودی پس از
Fill واقعی، و آزمون مثبت خرید/فروش/Partial/Cancel/کارمزد واقعی.
نام Modeها و Stateها قراردادند، نه اثبات اجرای همهٔ گردش‌های مالی.
این موارد علاوه بر مجوز حساب، کار نرم‌افزاری باز محسوب می‌شوند.

در بررسی این اجرا، `WALLEX_API_KEY` در محیط موجود نبود. محل `pass.txt` را
کاربر اعلام کرد، اما فایل باز، چاپ، انتقال یا Commit نشد. درخواست خصوصی صفر
بود. اعتبار پنج‌میلیونی، موجودی قابل استفاده/قفل‌شده، کارمزد، اجازهٔ معامله،
Package ID و فهرست بازارهای مجاز تأیید نشده‌اند. کلید را در چت نفرستید؛
فقط محیط فرآیند موردنظر باید آن را داشته باشد.

اپراتور می‌تواند در ترمینال محلی، بدون چاپ یا ذخیرهٔ کلید، آن را وارد کند
و بررسی خواندنی را در **همان ترمینال** اجرا کند؛ این کار کلید را به محیط
فرآیند فعلی Codex منتقل نمی‌کند و مجوز سفارش واقعی نیست:

```powershell
$atlasSecureKey = Read-Host 'WALLEX_API_KEY (local only)' -AsSecureString
$env:WALLEX_API_KEY = [Net.NetworkCredential]::new('', $atlasSecureKey).Password
conda run --no-capture-output -n shbk python -m wallex_bot.atlas_live_readiness --private-read
Remove-Item Env:WALLEX_API_KEY
```

هر دو متد submit/cancel جدید عمداً خطای ایمنی می‌دهند. Broker قدیمی نیز
HARD_DISABLED است. بازبینی مدل یا خبر نمی‌تواند این مرز را باز کند. ADD مجاز نشده است.

## ۳. موعد و ناظر مستقل

زمان تهران: توقف ورود ۲۲:۵۰، خروج ۲۳:۰۰، توقف نهایی ۲۳:۵۰ در ۲۰۲۶-۱۰-۲۳

ناظر فعلی مشاهده‌گر است و خروج مالی خودکار ندارد. مانده، Dust و سفارش واقعی
تأیید نشده‌اند؛ هیچ تضمین تسویه یا فروش کامل وجود ندارد.

```powershell

```

## ۶. تست‌ها و بازتولید

Baseline اعلام‌شده: ۳۱۹ موفق، ۵ Skip. اجرای کامل اولیهٔ این توسعه:
۳۳۳ موفق، ۵ Skip و یک شکست آزمون زمان‌بندی حافظه. اصلاح تست تنها منتظر زمان
واقعی پس از ثبت می‌ماند؛ شرط PIT، Hash و Chain تضعیف نشده است. اجرای کامل
بعدی: **۳۳۵ موفق، ۵ Skip**. نتایج نهایی توسعه در گزارش‌های XML/JSON همین شاخه
ثبت می‌شوند؛ عدد گزارش قبلی به‌جای اجرای جدید استفاده نشده است.

نتیجهٔ نهایی روی Commit بالا: **۳۴۱ موفق، ۵ Skip، صفر شکست/خطا**.
Clone واقعاً از GitHub دریافت شد، بدون کپی آرشیو یا وزن خصوصی:
**۲۳۸ موفق، ۱۰۸ Skip، صفر شکست/خطا**. Lock در محیط CPU ایزولهٔ موجود دوباره
بررسی شد؛ تمام نیازمندی‌ها از قبل نصب بودند و `pip check` موفق بود. این
مرحله ساخت و نصب یک محیط تازه از صفر نیست. Preflight میزبان PASS و
Preflight Clone به‌درستی به‌دلیل نبود آرشیو/وزن BLOCKED است.

در توسعهٔ تست جدید فونت نیز یک بار ۳۴۰ موفق، ۵ Skip و یک شکست import ثبت شد؛
لود ماژول تست با مسیر واقعی فایل اصلاح و کل مجموعه دوباره اجرا شد. تغییر
آزمون‌ها هیچ دادهٔ مالی ساختگی تولید نکرد. اجرای اولیه با افزونه‌های خودکار
محیط معطل و متوقف شد؛ هیچ نتیجهٔ موفقی برای آن ادعا نشده است.

رسیدها: `reports/final_readiness_verification.json`، XMLهای میزبان و Clone،
`final_readiness_preflight.json`، `final_readiness_secrets_scan.json`،
`final_readiness_account.json` و `final_readiness_ui.json`.
اسکن کل تاریخچهٔ قابل دسترس موفق است؛ محتوای ZIPها جداگانه بررسی شده است.

بررسی تصویری Desktop و جست‌وجوی واقعی ابزار/انتخاب Bollinger انجام شد؛
قابلیت تغییر Viewport موبایل در ابزار مرورگر در دسترس نبود. CSS واکنش‌گرا
تست ساختاری دارد، اما آزمون تصویری موبایل ادعا نمی‌شود. نمودار NAV پویا،
نمایش وضعیت زندهٔ حساب و کنترل مالی احرازشده همچنان تحویل نشده‌اند.

```powershell
$env:PYTEST_DISABLE_PLUGIN_AUTOLOAD='1'
conda run --no-capture-output -n shbk python -m pytest -q
conda run --no-capture-output -n shbk python scripts/judge_preflight.py
conda run --no-capture-output -n shbk python -m wallex_bot.atlas_console --port 8766
```

Preflight واقعی روی آرشیو میزبان PASS و `pip check` محیط ایزولهٔ موجود موفق
بود. Clone بدون آرشیو/وزن باید کمبود را صریح گزارش کند و تست‌های داده‌محور
را Skip کند. نتیجهٔ Clean Clone و Push/PR باید با Commit آزموده‌شده در رسید
انتشار ثبت شود؛ صرف موفقیت محیط قبلی اثبات نسخهٔ جدید نیست.
