# سناریوی پنج‌دقیقه‌ای نمایش — فقط شواهد واقعی

این سند اسکریپت است، نه ویدئوی ضبط‌شده.

برای نسخهٔ تحویل GitHub، UI واقعی را با `python -m wallex_bot.atlas_console --port 8766` اجرا و از http://127.0.0.1:8766 استفاده کنید. ابتدا preflight، سپس Overview، AI Research/Patterns، Tool Catalog و Evidence را نشان دهید. آمار نصب/تست امروز در گزارش تحویل و reports/m8_followup_test_results.json است؛ آمار قدیمی M8 snapshot تاریخی است. هیچ حساب، کلید، فایل خصوصی یا دکمهٔ فعال‌سازی LIVE در Demo نمایش داده نشود. موعد ایران و عدم تضمین تسویه طبق TRADING_DEADLINE_1405_08_01_FA.md توضیح داده شود.

۰:۰۰–۰:۴۰: گزارش M8 و وضعیت HARD_DISABLED را نشان دهید. سرمایهٔ Shadow فرضی را از موجودی تأییدشدهٔ مسابقه متمایز کنید؛ هیچ صفحهٔ کلید یا فایل خصوصی نمایش داده نشود.

۰:۴۰–۱:۳۰: وضعیت نشست و Sync را با فرمان‌های README نمایش دهید. زمان واقعی شروع، تعداد quote، forecast و امتیازهای بالغ را از خروجی همان لحظه بخوانید. اگر PENDING یا شکاف دارد، همان را بگویید؛ مدت قرارداد را uptime معرفی نکنید.

۱:۳۰–۲:۲۰: `m8_pattern_retrieval_results.json` را باز کنید: پنجره‌های واقعی ۷/۱۰، منبع و هش، embargo و تفکیک تحلیل retrospective از PIT. خروجی مشابهت را سود یا confidence کالیبره‌شده ننامید.

۲:۲۰–۳:۲۰: یک نمونهٔ واقعی از `m8_explainability_samples.json` انتخاب کنید. ده نقش، اختلاف‌نظر، دلیل veto و تصمیم نهایی را نشان دهید. اگر تصمیم STAY_IN_CASH است، برای نمایش معامله نسازید. خبر NC/دادهٔ ناکافی حق دورزدن ریسک ندارد.

۳:۲۰–۴:۱۰: replay را اجرا و یکسان‌بودن review و حفظ cash را بررسی کنید. برای noop، gate_identical می‌تواند null باشد؛ این اثبات اجرای مسیر خرید نیست. حالت‌های مسدود ADD و REBALANCE چندمرحله‌ای را توضیح دهید.

۴:۱۰–۵:۰۰: نتیجهٔ واقعی pytest، manifest و جدول پوشش نیازمندی‌ها را نشان دهید. نبود شواهد سود خالص، نیاز به مشاهدهٔ پیوسته و هزینهٔ تأییدشده را صریح بگویید. به جای تخمین امتیاز ۳۰۰، شواهد هر معیار و موارد باز را معرفی کنید.
