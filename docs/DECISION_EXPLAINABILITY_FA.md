# قرارداد توضیح و Replay تصمیم

لاگ مرجع M8، `agentic_decisions.sqlite.agentic_decisions_v8` در پوشه مستقل نشست است. وضعیت حساب در همان پوشه در `shadow.sqlite` باقی می‌ماند. رویدادهای قدیمی پاک یا به قالب جدید تبدیل نمی‌شوند.

هر تصمیم ثبت‌شده شامل Evidence کامل، Review، Intent، Allocation و ورودی‌های آن، Receipt Broker و Hash کانونی است. از جمله: زمان، نماد، Quote SHA، وضعیت قبل/بعد حساب، q10/q50/q90 و مدل، هزینه، Technical، شناسه خبر، Matchهای تاریخی، حافظه، اختلاف Agentها، وزن/مقدار پیشنهادی، ورودی و پاسخ Gate، علت عدم‌اقدام/رد و وضعیت فرضی Shadow.

قیمت/خبر/نتیجه در توضیح ساخته نمی‌شود. دلایل توضیح از فیلدهای واقعی Receipt گرفته می‌شوند؛ `STAY_IN_CASH` و `NO_PAPER_MUTATION` نیز قابل بررسی‌اند. اگر Gate اصلاً به علت عدم‌اقدام فراخوانی نشده باشد، فیلد Gate برابر null است، نه «مجوز صادر شد».

Receipt Hash با بازسازی JSON کانونی کنترل می‌شود. Replay:

1. از Evidence اصلی همان Review قطعی را بازتولید می‌کند.
2. در صورت وجود تصمیم Gate، همان تابع ریسک و همان ورودی را دوباره ارزیابی می‌کند.
3. رابطه نقد قبل + تغییر نقد فرضی = نقد بعد را بررسی می‌کند.
4. نبود Exchange Fill را کنترل می‌کند.

Replay حافظه جدید، Quote تازه، سفارش یا آموزش تولید نمی‌کند. Hash صحیح، صحت قیمت صرافی یا موفقیت اجرای واقعی را اثبات نمی‌کند؛ فقط یکپارچگی بایت‌ها و قرارداد محاسبه را نشان می‌دهد. تطابق ثبت‌شدهٔ Replay نیز جای Backtest مستقل و ارزیابی آینده‌نگر کافی را نمی‌گیرد.

```powershell
conda run --no-capture-output -n shbk python -m wallex_bot.atlas_intelligence replay
```

فایل `reports/m8_explainability_samples.json` فقط نمونه‌های واقعاً ثبت‌شده را نمایش خواهد داد؛ اگر هنوز تصمیمی ثبت نشده باشد، وضعیت Pending/Insufficient گزارش می‌شود و مثال عددی جعلی جایگزین نمی‌شود.
