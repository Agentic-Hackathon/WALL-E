# WALL-E — گزارش اجرای ارزیابی مالی و Spot کنترل‌شده

## ۱. نتیجه و منبع پیاده‌سازی

شاخهٔ مستقل `codex/financial-evaluation-spot` از مبنای تأییدشدهٔ `514a07b` ساخته شد. پیاده‌سازی واقعی انجام شده، اما **LIVE مجاز یا تأییدشده نیست** و هیچ سفارش واقعی ارسال نشده است.

از ماژول‌های موجود Atlas برای بازپخش M8، DataSync، مدل‌ها، اخبار، LangGraph/SqliteSaver، حافظه، Portfolio، PaperAccount، زنجیرهٔ رسیدها، RiskGate و Deadline استفاده شد. Champion، Recipe آن، دو Transformer، Checkpointها و شش فایل هستهٔ محافظت‌شده تغییر نکردند. داده‌ها و نشست‌های قبلی پاک یا بازنویسی نشدند.

آداپتور Spot مستقل با تکیه بر قراردادهای رسمی [حساب Spot/حساب اعتباری](https://developers.wallex.ir/docs/spot-intro)، [ایجاد سفارش](https://developers.wallex.ir/docs/spot-create-order)، [جزئیات سفارش](https://developers.wallex.ir/docs/spot-single-order-detail)، [سفارش‌های باز](https://developers.wallex.ir/docs/spot-active-orders) و [لغو سفارش](https://developers.wallex.ir/docs/spot-cancel-order) نوشته شد. کد خارجی کپی نشده؛ قرارداد API مجوز کپی کد محسوب نشده است. هزینه، قوانین و موفقیت مالی هیچ ریپوی دیگری به Atlas نسبت داده نشده‌اند.

منطق جدید: حساب فرعی صریح با `sub-account-client-id`، Manifest محلیِ محدود به حساب/پکیج/بازار/سرمایه/انقضا، ارجاع هش‌تأییدشده به شواهد، ARM تعاملی محلی حداکثر ۳۰۰ ثانیه، عدم ماندگاری ARM پس از Restart، اتصال هویت کلید به همان پردازه، مجوز یک‌بارمصرف برای درخواست دقیق پس از RiskGate، قفل SQLite چندپردازه، وضعیت UNKNOWN بدون Retry مالی، حسابداری Decimal و Reconciliation مستقل موجودی. سفارش باز دیگر، حتی با جهت همسان، مانع ورود جدید است. برداشت/اهرم/شورت وجود ندارد.

## ۲. فایل‌ها و روش اجرا

فایل‌های اصلی: `wallex_bot/atlas_finance.py`، `atlas_finance_control.py`، `atlas_spot_runtime.py`؛ اصلاحات `atlas_study.py`، `atlas_agentic_cycle.py`، `atlas_dynamic_shadow.py`، `atlas_spot_exchange.py`، `atlas_live_readiness.py`، `atlas_console.py` و `static/console_v2.js`. تست‌های جدید در `tests/test_financial_runtime_safety.py` هستند. نتایج قابل ماشین‌خواندن: `reports/financial_evaluation_results.json`.

در Git Bash ابتدا مسیر را این‌گونه وارد کنید:

```bash
cd /d/Hackaton/Wallex/wallex_agent_v3
```

فرمان‌های اجرا از ریشهٔ پروژه:

```text
conda run --no-capture-output -n shbk python -m wallex_bot.atlas_live_readiness --private-read
conda run --no-capture-output -n shbk python -m wallex_bot.atlas_finance account-status
conda run --no-capture-output -n shbk python -m wallex_bot.atlas_finance backtest
conda run --no-capture-output -n shbk python -m wallex_bot.atlas_finance shadow-prepare
conda run --no-capture-output -n shbk python -m wallex_bot.atlas_finance shadow-run --max-runtime-seconds 120
conda run --no-capture-output -n shbk python -m wallex_bot.atlas_finance shadow-stop
conda run --no-capture-output -n shbk python -m wallex_bot.atlas_finance shadow-run --resume --max-runtime-seconds 65
conda run --no-capture-output -n shbk python -m wallex_bot.atlas_console --port 8767
```

کلید فقط از محیط همان پردازه خوانده می‌شود. محیط ترمینال شخصی به پردازهٔ موجود دیگری منتقل نمی‌شود. `pass.txt` یا کلید در کد، مرورگر، گزارش یا Git خوانده/نوشته نشده است. فرمان خواندنی موفق اولیه را خود اپراتور در ترمینال دارای کلید اجرا کرد؛ اجرای Shadow از آن کلید استفاده نکرد.

اگر سورس یا محیط/مدل عوض شد، Resume نشست یخ‌زده عمداً رد می‌شود. برای شروع یک نشست **جدید**، `shadow-prepare --new-session` را اجرا کنید؛ شواهد قبلی حفظ می‌شوند. Source manifest شامل اسکریپت‌های محلی نیز هست؛ Clean Clone بدون همان دارایی‌ها، همان نشست تاریخی نیست.

صفحهٔ «ارزیابی مالی» سه تب Backtest، Shadow و Real دارد. Start/Stop فقط Shadow است؛ Start یک اجرای محدود ۱۲۰ثانیه‌ای است، نه سرویس دائمی. خواندن وضعیت هر ۱۰ ثانیه، رسید خواندنی حساب، سفارش‌های واقعیِ ثبت‌شده و هش‌تأییدشده، کارمزدهای ثبت‌شده، منحنی NAV فرضی، تصمیم‌ها، پیش‌بینی‌ها، RiskGate و موعد جدا نمایش داده می‌شوند. نبود موجودی/PnL واقعی، صفر نمایش داده نمی‌شود. API خواندن حساب از رابط فراخوانی نمی‌شود؛ رسید واردشده اتصال فعلی نیست. مسیر کنترل محلی به Host/Origin دقیق و nonce هر سرور نیاز دارد؛ مسیر سفارش یا ARM در UI نیست.

آداپتور واقعی فقط با `atlas_spot_runtime reconcile` یا `interactive` و مسیرهای صریح Authorization/Forecast قابل فراخوانی است. عمداً Manifest مجاز ساختگی یا فرمان آمادهٔ ARM تولید نشده است؛ ورودی‌های لازم هنوز تأیید نشده‌اند. Broker قدیمی HARD_DISABLED باقی است. پیاده‌سازی آداپتور به معنی تأیید اتصال مالی آن نیست.

## ۳. اجرای واقعی و تست‌ها

بازپخش زمانی رسیدهای استراتژی موجود: ۱۰ تصمیم، صفر انتقال Paper، نقد/NAV فرضی ۵ میلیون TMN، سود خالص مشاهده‌شده صفر و افت مشاهده‌شده صفر. پنج تصمیم به‌علت پوشش‌ندادن هزینه توسط Q10 و پنج تصمیم به‌علت تأییدنشده‌بودن تکنیکال در نقد ماندند. این بازپخش، Backtest اجرایی بلندمدت نیست؛ دفتر سفارش تاریخیِ PIT و ورودی‌های اجرای تاریخی کافی نداریم و Fill از قیمت Close ساخته نشد. نرخ قدیمی رسیدها بازنویسی نشد.

نشست نهایی `financial_1792751480804788500` با سورس معاملاتی `1af75abf19bcb6e003b984e934dbf40009d08c9f` و قرارداد `9b23ae54db078da835fe885e8c5157436555d234f394a39a20c1310cab76453f` اجرا شد. Commitهای بعدی مستند/نمایش را از سورس معاملاتیِ آزمایش‌شده متمایز می‌کنند.

دو اجرای محدود ۱۲۰ و ۶۵ ثانیه با توقف/شروع مجدد: هشت رسید عمق واقعی، ۱۰ پیش‌بینی از پنج مدل روی BTC/ETH، هشت تصمیم با ۱۰ Agent، صفر انتقال Paper، صفر سفارش واقعی، PnL فرضی صفر و افت مشاهده‌شده صفر. چهار دلیل Q10 و چهار دلیل تکنیکال ثبت شد. Portfolio و RiskGate وارد مسیر شدند؛ هیچ آستانه‌ای برای ساخت معامله پایین آورده نشد. بازهٔ درخواست‌های عمق تقریباً ۱۰:۳۱:۴۲ تا ۱۰:۳۶:۴۹ UTC است و توقف بین دو اجرا دارد؛ مطالعهٔ پیوستهٔ ۴۸ساعته نیست.

Restart: تعداد پیش‌بینی ۱۰ باقی ماند و هش مجموعهٔ شناسه‌ها یکسان بود؛ تعداد Quote از چهار به هشت رسید. Stop از endpoint واقعی رابط پاسخ ۲۰۰ داد و درخواست Stop با Resume بایگانی شد. یک پردازهٔ رقیب با `FINANCIAL_RUNNER_HELD_NO_REQUESTS` و بدون شبکه برگشت. ساعت پس از خروج از پردازه ابطال شد.

شمارش دسته‌های ثبت‌شده در دو اجرای نهایی: هشت درخواست عمق موفق و صفر خطای عمق؛ دو Chunk جدید DataSync، صفر Failed و صفر Cache Hit در همان چرخه؛ شش تلاش خبر شامل خطای GDELT/Coindesk؛ ۱۳ درخواست بررسی ساعت. این ارقام فقط دسته‌های instrument‌شدهٔ نشست نهایی‌اند، نه کل ترافیک دستگاه/تلاش‌های قبلی. کل اخبار جدید در نشست نهایی صفر بود؛ در تلاش اولیهٔ جدا، ۱۳ عنوان واقعی جدید وارد آرشیو شده بود. FinBERT به‌دلیل محدودیت مجوز در تصمیم مسابقه غیرفعال ماند.

آزمون نهایی:

```powershell
$env:PYTEST_DISABLE_PLUGIN_AUTOLOAD='1'
conda run --no-capture-output -n shbk python -m pytest -q
```

**۳۵۷ passed، ۶ skipped، صفر failure**. پنج Skip قبلی حفظ شده و یک Skip صریح برای نبود ضبط مجاز Fill واقعی اضافه شده است. تست مثبتِ Fill/Partial Fill/کارمزد واقعی جعل نشده است. تست‌های جدید دادهٔ بازار ساختگی ندارند: کنترل مجوز، نبود شبکه قبل از مجوز، Idempotency، UNKNOWN پس از Restart، دست‌کاری زنجیره، جداسازی حالات، CSRF/Origin و قفل چندپردازه را با متادیتای کنترلی یا رسیدهای واقعی موجود می‌سنجند.

اسکن Gitleaks نسخهٔ ۸٫۳۰٫۱ روی کل تاریخچهٔ HEAD در `1938c96` PASS بود؛ پس از Commit گزارش نیز دوباره بررسی می‌شود. دادهٔ خصوصی حساب در گزارش قابل انتشار درج نشده و رسید خام فقط در `atlas_store/operations/private_account_read.json` محلی و ignored است.

## ۴. این تغییر چه چیزی را اثبات نمی‌کند؟

سودآوری، برتری خارج از نمونه، کالیبراسیون آیندهٔ این ۱۰ پیش‌بینی، معامله‌پذیری تاریخی، اجرای مثبت خرید/فروش واقعی، Partial Fill واقعی، کارمزد و بقای موجودی پس از Fill واقعی، یا تسویهٔ کامل را اثبات نمی‌کند. افق پیش‌بینی ۲۷۰۰ ثانیه است و در زمان ثبت این گزارش هیچ Outcome این نشست بالغ و امتیازدهی‌شده نبود. صفر PnL همراه صفر معامله نشانهٔ مزیت اقتصادی نیست.

اتصال خواندنی موفق و مشاهدهٔ زیرحساب فعال `prop`، به‌تنهایی هویت/اعتبار مسابقه یا تعلق موجودی به آن زیرحساب را ثابت نمی‌کند. نرخ واقعیِ مشاهده‌شدهٔ حساب برای Shadow، ۰٫۳٪ Taker است؛ نرخ مسابقهٔ حساب فرعی تا خواندن account-scoped تأیید نیست. تاریخ معتبر داخلی در رسید قدیمی وجود ندارد و mtime جای آن را نگرفته است.

## ۵. اثر و محدودیت موعد

بازتولیدپذیری، کیفیت شواهد، حسابداری، کنترل ریسک مستقل از LLM، جداسازی Paper/Real، Stop/Resume و قابلیت بررسی داور بهتر شد. افزایش امتیاز یا سود تضمین نشده است. تاریخ ۲۳ اکتبر ۲۰۲۶، توقف ورود ۲۲:۵۰، مرحلهٔ خروج ۲۳:۰۰ و HALT در ۲۳:۵۰ تهران حفظ است. ARM خودکار پس از Restart/موعد وجود ندارد. پس از HALT فقط بررسی خواندنی و گزارش باقیمانده مجاز است؛ تسویه بدون Fill واقعی موفق اعلام نمی‌شود.

ناظر مستقل Deadline موجود است اما سرویس دائمی نصب و تأیید نشده؛ مرورگر یا اجرای محدود Shadow جای آن نیست. UI و Shadow اکنون مجوز معاملهٔ LIVE ندارند. نشست‌های تست پایان یافته‌اند؛ سرور UI محلی فقط برای نمایش/کنترل صریح پژوهش باقی است و معاملهٔ پس‌زمینه‌ای فعال نیست.

## ۶. اطلاعات و شواهد باقی‌مانده

برای ادامهٔ بررسی مجوز، شناسهٔ دقیق حساب فرعی و پکیج، سند تعلق اعتبار، Allowlist رسمی، Tick/Step/Minimum واقعی و مجوز Trade همان حساب لازم است. کلید را در چت نفرستید. برای تأیید مسیر مثبتِ قرارداد اجرای واقعی، ضبط مجاز و امن پاسخ‌های واقعی سفارش/Fill/لغو/کارمزد و موجودی قبل/بعد لازم است؛ بدون ارسال سفارش آزمایشی خودکار. سپس شواهد اقتصادی مستقل، نصب ناظر Deadline، تأیید آگاهانهٔ نشست و سقف سرمایهٔ اپراتور لازم‌اند. این گزارش مجوز فعال‌سازی LIVE نیست.
