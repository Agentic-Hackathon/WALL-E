# اصلاح موعد به ۳ آبان ۱۴۰۵

درخواست صریح اپراتور: جایگزینی موعد ۱ آبان با **یکشنبه ۳ آبان ۱۴۰۵ / ۲۵ اکتبر ۲۰۲۶ ساعت ۲۳:۵۰ Asia/Tehran**. این ثبت، ادعای تأیید تغییر مقررات از سوی برگزارکننده نیست.

## قرارداد جدید

| رویداد | تهران، ۲۵ اکتبر | UTC، ۲۵ اکتبر |
|---|---|---|
| توقف ورود جدید | ۲۲:۵۰ | ۱۹:۲۰ |
| آغاز مرحله خروج | ۲۳:۰۰ | ۱۹:۳۰ |
| HALT نهایی | ۲۳:۵۰ | ۲۰:۲۰ |

در این تاریخ DST برلین پایان یافته و موعد برابر ۲۱:۲۰ برلین است؛ مبنا همچنان تهران است، نه ساعت دستگاه. فقط تاریخ قرارداد مرکزی تغییر کرده؛ محدودیت ریسک، ساعت معتبر، حساب، مجوز، ARM و کنترل سفارش تغییری نکردند. این لایه اختیار را محدود می‌کند؛ تبدیل موفق به TMN را بدون Fill واقعی تضمین نمی‌کند.

## پیاده‌سازی و منابع

`atlas_deadline.DEADLINE` به ۲۵ اکتبر تغییر کرد. ENTRY_STOP و UNWIND_START از همان ثابت مشتق می‌شوند. همهٔ مصرف‌کنندگان موجود شامل آداپتور Spot، Finance و ناظر مستقل همین قرارداد را وارد می‌کنند. تاریخ نمایشی `console_v2.js` اکنون از پاسخ API گرفته می‌شود، نه literal ثابت. زیرساخت داخلی و zoneinfo بازاستفاده شدند؛ کتابخانه، ریپوی بیرونی یا کد جدید ثالث لازم نبود. README فارسی/انگلیسی، راهنمای نسخه جاری و ابتدای سند موعد قبلی به‌روز شدند؛ گزارش‌های تاریخی مالی بازنویسی نشدند.

## نشست‌ها و توقف ماندگار

هیچ study_contract، Forecast، حافظه، SQLite، داده یا مجوز قبلی دست‌کاری نشد. تغییر منطق موعد، Source Manifest را تغییر می‌دهد؛ Resume قرارداد قدیمی با سورس جدید عمداً رد می‌شود. برای مطالعهٔ جدید با تاریخ تازه:

```text
conda run --no-capture-output -n shbk python -m wallex_bot.atlas_finance shadow-prepare --new-session
conda run --no-capture-output -n shbk python -m wallex_bot.atlas_finance shadow-run --max-runtime-seconds 3600
```

این فرمان‌ها خودکار اجرا نشدند. در بررسی پیش از تغییر، Lease مطالعهٔ قبلی فعال نبود. اگر ناظر از قبل HALTED ثبت کرده باشد، تمدید تاریخ آن را پاک نمی‌کند. HALT حساب Spot با موعد قبلی نیز برای بازبینی دستی بسته می‌ماند؛ هیچ بازفعال‌سازی خودکاری رخ نمی‌دهد.

## اجرای واقعی و تست

پردازه‌های تکراری صرفاً مربوط به سرور نموداری 8769 با تطبیق فرمان اجرایی شناسایی و بسته شدند؛ پردازه Shadow یا سرور دیگر هدف قرار نگرفت. سرور جدید روی همان پورت راه افتاد. GET واقعی `/api/overview` موعد `2026-10-25T23:50:00+03:30`، توقف ورود `2026-10-25T22:50:00+03:30` و آغاز خروج `2026-10-25T23:00:00+03:30` را برگرداند؛ LIVE همچنان HARD_DISABLED و live_armed=false بود.

تست‌های متمرکز: **۴۹ passed**. مجموعه کامل نهایی: **۴۰۰ passed، ۶ skipped** در ۴۰٫۰۹ ثانیه، با `PYTEST_DISABLE_PLUGIN_AUTOLOAD=1` در shbk. اجرای sandbox یک خطای اتصال محلی Windows 10053 در تست قدیمی HTTP داشت؛ اجرای نهایی خارج از محدودیت شبکه موفق بود. یک خطای اولیهٔ جداکننده مسیر Windows در تست تطبیق Manifest نیز اصلاح شد، بدون تغییر یا پاک‌کردن قرارداد منجمد. تست جدید عبور از مرزهای تاریخ، تغییر DST، حفظ HALT قدیمی، ممنوعیت ARM خودکار و رد Resume را بررسی می‌کند؛ هیچ داده بازار ساختگی اضافه نشده است.

## حدود نتیجه

این تغییر، تمدید نرم‌افزاری موعد است، نه اثبات صلاحیت LIVE، سودآوری، مجوز برگزارکننده یا تسویه کامل. برای اثر تاریخ جدید در هر پردازه قدیمی، Restart همان پردازه لازم است؛ رابط 8769 از قبل با نسخه جدید راه‌اندازی شده. توقف‌های ماندگار قبلی نیازمند بازبینی مستقل‌اند و در این کار حذف نمی‌شوند.
