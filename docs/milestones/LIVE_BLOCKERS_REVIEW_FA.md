# بازبینی موانع اجرای LIVE — ۲۳ اکتبر ۲۰۲۶

## ۱. نتیجه و منابع

LIVE فعال نشده و هیچ سفارش واقعی ارسال نشده است. اتصال خواندنی کلید جاری موفق است؛ عوض‌کردن دوباره کلید بر اساس شواهد فعلی راه‌حل نیست. تأیید انسانی اپراتور درباره Trade و سقف ۵۰۰ هزار تومان شامل هزینه‌ها حفظ شده، اما به گواهی API یا نشست مسلح تبدیل نشده است.

کد اتصال موجود و قراردادهای رسمی زیر بازاستفاده شده‌اند؛ کد بیرونی جدیدی کپی نشده و commit/لایسنس جدید ریپوی خارجی مطرح نیست:

- https://developers.wallex.ir/docs/spot-intro — کلید حساب اعتباری و هدر حساب فرعی هر دو لازم‌اند.
- https://developers.wallex.ir/docs/spot-active-markets — precision و وضعیت Spot مستند هستند، اما این‌ها به‌تنهایی حداقل مبلغ سفارش را ثابت نمی‌کنند.

## ۲. تغییرات واقعی و اجرا

- `atlas_live_readiness.py`: گزارش ثابت و گمراه‌کننده «همه چیز فاقد مدرک» با مشاهده واقعی زمینه حساب و کارمزد جایگزین شد. اتصال خواندنی، مجوز معامله محسوب نمی‌شود. هیچ موفقیت قدیمی جای شکست خواندن جدید قرار نمی‌گیرد.
- بارگذاری `.env` فقط با آرگومان صریح و فقط فایل محلی پروژه ممکن است؛ متغیر صادرشده محیط بر فایل مقدم است. کلید چاپ، بازنویسی یا وارد Git نمی‌شود.
- اصلاحات اجرایی موجود در working tree بازبینی و تست شدند: قابلیت شبکه یک‌بارمصرف و مقید به حساب، بررسی وضعیت با GET پس از ACK، عدم ارسال مجدد وضعیت UNKNOWN، قفل بازیابی، توقف ماندگار پس از موعد و خروج نهایی مستقل از بقای Forecast. این‌ها رفع نقص نرم‌افزارند، نه اثبات اجرای موفق صرافی.
- اصلاح کارمزد ثبت Forecast برای نشست‌های آینده و ابزار تشخیص فقط‌خواندنی حفظ شدند؛ نشست تاریخی و پیش‌بینی‌های قبلی بازنویسی نشدند.

فرمان خواندنی (نه فرمان شروع معامله):

```text
conda run --no-capture-output -n shbk python -m wallex_bot.atlas_live_readiness --env-file .env --private-read --package-id 183
```

دو اجرای موفق کشف حساب، هر یک ۸ درخواست GET داشتند. یک اجرای اولیه در sandbox شکست شبکه خورد و جدا ثبت شد؛ بعد از دسترسی شبکه، اتصال موفق شد. بررسی جداگانه ساعت و سفارش‌های باز نیز فقط GET بود.

در حدود ۱۸:۳۵ تهران: موجودی آزاد و کل ۵ میلیون TMN، مسدودی صفر؛ کارمزد BTC/ETH میکر ۰٫۲۵٪ و تیکر ۰٫۳٪. جزئیات پکیج ۱۸۳ دریافت شد، اما تاریخچه آن با و بدون زمینه حساب 401 داد. BTC/TMN و ETH/TMN در فهرست ممنوعه این پکیج نیستند؛ این مشاهده جای مجوز مستقل برگزارکننده را نمی‌گیرد. هیچ شناسه خصوصی یا کلیدی در این گزارش منتشر نشده است.

بررسی جداگانه ساعت: اختلاف حدود ۰٫۵۰ ثانیه، رفت‌وبرگشت ۰٫۷۷ ثانیه، verified=true در همان لحظه؛ تعداد سفارش باز حساب صفر. این نمونه ساعت، سرویس دائمی نظارت نیست و بعداً منقضی می‌شود. رسید در `atlas_store/operations/live_readonly_preflight.json` محلی و ignored است.

## ۳. تست

اجرای کامل با `PYTEST_DISABLE_PLUGIN_AUTOLOAD=1` و `conda run --no-capture-output -n shbk python -m pytest -q`: **۳۷۸ passed، ۶ skipped** در ۶۵٫۴۵ ثانیه. تست‌ها از رسید واقعی موجود یا metadata کنترل غیرمالی استفاده می‌کنند؛ نبود رسید مالی با Skip گزارش می‌شود، نه داده جایگزین. این نتیجه مربوط به کل working tree آزموده‌شده است، نه ادعای clean clone فاقد رسیدهای محلی.

## ۴. چه چیزی اثبات نشده است؟

این تغییرات اجرای واقعی Submit/Cancel، موفقیت Partial Fill، سودآوری، یا صلاحیت اقتصادی مدل را اثبات نمی‌کنند. مسیر مثبت Fill هنوز رسید واقعی مجاز ندارد. قرارداد فعلی broker مدرک `AUTHORIZED_REAL_EXECUTION_AND_INDEPENDENT_VALIDATION` می‌خواهد؛ ساختن فایل verified=true برای شروع اولین معامله، مدرک نیست و انجام نشد. حل این وابستگی نیازمند سیاست راه‌اندازی مستقل و بازبینی‌شده یا رسید معتبر است، نه حذف پنهانی شرط امنیتی.

بررسی فقط‌خواندنی مطالعه ثابت: ۷۲ Quote، ۴۰ Forecast، ۱۰ outcome با Quote واقعی آینده. ۳۰ Forecast هنوز در پایگاه PENDING مانده‌اند و نباید بدون Quote در پنجره مجاز امتیاز ساختگی بگیرند. ۷۲ تصمیم، صفر معامله، سود و زیان فرضی صفر و سود واقعی نامعلوم. در همه ۷۲ تصمیم q10 خام هزینه تخمینی را پوشش نداده؛ ۳۶ تصمیم مانع فنی هم دارند. ۱۰ outcome تنها دو رویداد بازار مشترک میان پنج مدل هستند، نه ۱۰ آزمون اقتصادی مستقل.

در Forecastهای تاریخی، کارمزد metadata برابر پیش‌فرض قدیمی بوده است (۴۰ مورد)؛ این داده‌ها تغییر نکردند. محاسبه مجدد proxy با نرخ ۰٫۳٪ هر سمت برای BTC حدود ‎−۰٫۷۵۵٪ و ETH حدود ‎−۰٫۷۷۴٪ بازده لگاریتمی است؛ این‌ها اجرای counterfactual سرخط دفتر سفارش‌اند، نه Fill، PnL یا شواهد برتری مدل. تشخیص کامل فقط در `atlas_store/operations/live_financial_diagnostics.json` نگهداری شد.

## ۵. اثر و موانع باقی‌مانده

شفافیت حساب، کنترل اجرای سفارش، بازیابی و بازتولیدپذیری بهتر شده‌اند؛ امتیاز یا سود تضمین نشده است. RiskGate، Champion و مدل‌های محافظت‌شده تغییر نکردند.

موانع باز: اتصال قطعی حساب به پکیج، مرجع مستقل بازارهای مجاز، tick/step/minimum واقعی، مدرک مالی و اجرای مثبت معتبر، نشست و مجوز اجرایی بازبینی‌شده، تأیید محلی ARM و خوراک تازه ساعت/Quote. تأیید انسانی Trade با اثبات خواندنی API یکسان نیست؛ نبود endpoint اثبات Trade، به معنی اثبات نداشتن این دسترسی هم نیست.

موعد بدون تغییر: توقف ورود ۲۲:۵۰، خروج ۲۳:۰۰، HALT ساعت ۲۳:۵۰ تهران در ۲۳ اکتبر ۲۰۲۶. پس از HALT مسلح‌سازی خودکار ممنوع است؛ تسویه بدون Fill واقعی ادعا نمی‌شود.

## ۶. اطلاعات لازم از اپراتور/برگزارکننده

کلید جدید یا ارسال کلید در چت لازم نیست. شواهد اتصال حساب به پکیج و محدودیت دقیق BTC/TMN باید از والکس/برگزارکننده تهیه شود. شرط اقتصادی فعلی هم با دستور «شروع ترید» برطرف نمی‌شود؛ برای معامله استراتژی باید سیگنال تازه‌ای واقعاً از RiskGate عبور کند. این گزارش اعلام آمادگی LIVE نیست.
