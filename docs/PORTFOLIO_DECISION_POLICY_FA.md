# سیاست تصمیم پرتفوی پژوهشی M8

سرمایه آغاز حساب پژوهشی ۵ میلیون TMN فرضی است، نه موجودی تأییدشده حساب مسابقه. نسخه سیاست `ATLAS_DYNAMIC_SHADOW_V1` است. هیچ transport معامله واقعی وجود ندارد و LIVE سخت غیرفعال است.

## اختیار و وضعیت‌ها

`BUY / ADD / HOLD / REDUCE / SELL / REBALANCE / STAY_IN_CASH / REJECT` قراردادهای صریح‌اند، نه وعده اینکه همه آن‌ها توسط Gate فعلی مجازند.

- BUY فقط با Forecast ثبت‌شدهٔ Champion ثابت، Review بدون تغییر عددی مدل، Book واقعی تازه، شواهد Core و مجوز همان RiskGate بررسی می‌شود.
- مقدار BUY می‌تواند از سقف مجاز Gate کمتر باشد؛ نمی‌تواند آن را بیشتر کند. حداقل کاغذی قبلی حفظ شده و مقدار کمتر، به‌زور گرد نمی‌شود.
- HOLD/عدم‌اقدام نیز Receipt و دلیل دارد.
- SELL یا REDUCE فقط وقتی مجوز فروش کامل از Gate صادر شده باشد مجازند. کاهش کمّی زیر مجوز فروش کامل، permission تازه برای خروج دلخواه نیست.
- **ADD فعلاً توسط Gate موجود برای موقعیت نگه‌داری‌شده مجاز نیست.** این حالت Reject/Blocked می‌ماند. حذف موقعیت از ورودی Gate برای ساخت مجوز خرید ممنوع است.
- REBALANCE نیازمند خروج واقعاً ثبت‌شده و سپس بررسی تازه ورود است؛ نقد حاصل از فروش ناموفق پیش‌فرض گرفته نمی‌شود. این آداپتور سفارش مرکب یا Fill اتمیک صرافی ادعا نمی‌کند. انتقال سرمایه تنها در چرخه‌های گیت‌شده مستقل و زیر بودجه ممکن است؛ جابه‌جایی صرفاً به‌خاطر Forecast بزرگ‌تر مجاز نیست.

## سرمایه، هزینه و تازگی

همان RiskGate و مقادیر آن حفظ شده‌اند: سفارش حداکثر ۵۰۰هزار TMN، سرمایه باز حداکثر ۱میلیون، ورود حداکثر ۱۰٪ نقد، حداقل کاغذی ۱۰۰هزار، Spread حداکثر ۷۰bps و Drawdown سه درصد. M7 علاوه بر آن نقد حداقل ۸۰٪، وزن هر دارایی حداکثر ۱۰٪، Turnover حداکثر ۱۰٪ و هزینه حداکثر ۰٫۱٪ NAV را دارد.

پیشنهاد Confidence-aware از تابع M7 بازاستفاده می‌شود و برای ورود با نسبت محافظه‌کارانهٔ Marginِ q10 به پهنای Interval کاهش می‌یابد. این Sizing پژوهشی ثابت، Kelly یا بهینه‌سازی اثبات‌شده نیست. Volatility و Correlation از بازده‌های واقعی هم‌تراز می‌آیند؛ فقدان کنترل ضروری، تخصیص را رد می‌کند. covariance allocatorهای فاقد اعتبارسنجی مستقل فعال نشده‌اند.

NAV از نقد + Sweep کامل Bid واقعیِ دارایی‌های نگه‌داری‌شده، با فرض هزینه خروج به دست می‌آید. Bid نامعلوم، صفر یا قیمت ورود فرض نمی‌شود. Quote برای اقدام حداکثر ۳۰ ثانیه عمر دارد. خواندن موجودی، ارزیابی Gate، کنترل Turnover/Cost و تغییر حساب در تراکنش اتمیک همان SQLite انجام می‌شود. بودجه در Bucketهای ۱۵دقیقه‌ای ساعت واقعی مشترک است؛ چند Review روی Quoteهای جدید، بودجه را از نو نمی‌سازد. این زمان‌بندی امکان چند بررسی خروج در ساعت آخر را فراهم می‌کند، حتی وقتی ثبت Forecast تازه به‌علت نداشتن پنجره آینده متوقف شده است.

Sweep خرید/فروش فقط از سطوح واقعی Book محاسبه می‌شود و برآورد فرضی است. هیچ رکورد Exchange Fill ساخته نمی‌شود. Fee برابر ۰٫۱٪ هر طرف فرضِ تأییدنشده است؛ Tick/Lot/حداقل واقعی و کارمزد حساب احراز نشده‌اند. Decimal Precision معادل Tick/Step نیست.

## پایان دوره و داده ناکافی

پنجره خروج پژوهشی از یک ساعت مانده به Deadline اعلام‌شده شروع می‌شود تا چند چرخه زیر سقف Turnover امکان بررسی خروج داشته باشند. همان `final_tmn_liquidation` ریسک، عمق کافی Best Bid برای کل مقدار را لازم می‌داند؛ خروج تضمین نمی‌شود. نقد و هر دارایی تسویه‌نشده صریح باقی می‌مانند. Forecast جدیدِ دارای افق/پنجره پذیرش پس از پایان دوره، مجوز ورود تازه نمی‌سازد.

متن `file.txt` هم NAV پایان شامل دارایی باقی‌مانده و هم تحقق سود به تومان را ذکر می‌کند؛ ملاک رسمی نهایی باید با برگزارکننده روشن شود. هدف پژوهش ما خروج به TMN است، نه ادعای فروش موفق خودکار.

بدون Forecast مثبت بعد از هزینه، صفر معامله نتیجه مجاز است. در آرشیو موجود هیچ BUY/SELL کاغذی ثبت‌شده برای ساخت سناریوی مالی جعلی استفاده نشده است؛ تست‌های شاخه‌های مالیِ فاقد شواهد واقعی، محدودیت گزارش دارند. اجرای LIVE، تغییر Gate برای مجازکردن ADD و Promotion، مجوز جداگانه می‌خواهند.
