# Wallex Atlas V3 — ایجنت پژوهشی و سایه‌معاملاتی، با داده واقعی

**وضعیت نسخه:** قابل اجرا برای کشف بازار، آرشیو OHLCV، ابزارهای تکنیکال، News PIT، آموزش دو Transformer روی GPU، LangGraph، و Shadow؛ **ارسال سفارش واقعی غیرفعال است**. هیچ بازار غیرمجاز یا شناسه پکیج مجهولی حدس زده نمی‌شود.

## اجرای بدون تغییر فایل یا جایگزینی شناسه

در پوشه فایل ZIP استخراج‌شده و محیط `shbk`، تنها این فرمان را اجرا کنید:

```bash
bash start.sh
```

این دستور وابستگی‌ها را نصب می‌کند، تست‌های بدون داده ساختگی را اجرا می‌کند و سپس پروژه را با بازارهای واقعاً کشف‌شده از والکس اجرا می‌کند. اگر بسته MCP یا GPU در دسترس نباشد، خطای صریح رخ می‌دهد/بخش اختیاری رد می‌شود؛ نتیجه جعلی تولید نمی‌شود. API Key قبلی اگر هنوز در متغیر `WALLEX_API_KEY` محیط شما هست، فقط در درخواست خواندنی خصوصی مورد استفاده قرار می‌گیرد. **هرگز کلید را در فایل کد یا چت قرار ندهید.** برای بخش عمومی، API Key ضروری نیست.

اگر می‌خواهید فقط مرحله سبک‌تر را بررسی کنید:

```bash
python -m wallex_bot.atlas_cli status
python -m wallex_bot.atlas_cli discover
python -m wallex_bot.atlas_cli account-audit
python -m wallex_bot.atlas_cli mcp-smoke
```

## همه دارایی‌ها و همه تایم‌فریم‌های پشتیبانی‌شده

آرشیو تمام بازارهای اسپات کشف‌شده و تمام بازه‌های پشتیبانی‌شده بدون واردکردن نمادها:

```bash
python -m wallex_bot.atlas_cli archive-all
```

آرشیو پیش‌فرض، هفت روز اخیر را دربرمی‌گیرد. اگر طول بازه بیشتری می‌خواهید، `--days` قابل تنظیم است؛ داده قدیمی **اجباری نیست** و هدف معاملاتی همچنان ۴۸ تا ۷۲ ساعت آینده است. داده `1m,1h,1D` از API درخواست می‌شود؛ `5m,15m,30m,3h,4h,6h,8h,12h,2D,3D` با تجمیع دقیق داده واقعی منبع محاسبه می‌شوند. تمام بازه‌های مشتق‌شده در فایل و پایگاه‌داده، با منبعشان ثبت می‌شوند. فقط کندل‌هایی پذیرفته می‌شوند که تمام مشاهدات پایه آنها وجود داشته باشد. تمام رزولوشن‌های اعلامیِ API لزوماً به‌طور مستقل از سرور ارائه نمی‌شوند؛ این طراحی جلوی mislabeled candles را می‌گیرد.

ساختار ذخیره:

- `atlas_store/catalog.sqlite`: اطلاعات بازارها، زمان و هش دریافت، بازه‌های موجود/ناموجود.
- `atlas_store/candles/<SYMBOL>/<RESOLUTION>/*.csv.gz`: کندل‌های واقعی، تفکیک‌شده و بازاستفاده‌پذیر.
- `atlas_store/last_harvest.json`: وضعیت دانلود و خطاها.
- `atlas_store/research/all_strategy_results.csv`: نتایج بررسی همه استراتژی‌ها.
- `atlas_store/research/chronological_winners.csv`: انتخاب صرفاً از داده TRAIN.
- `atlas_store/news.sqlite`: اخبار واقعی و زمان اولین مشاهده.
- `atlas_store/models/*.pt`: چک‌پوینت مدل عمیق + JSON امتیاز اعتبارسنجی.
- `atlas_store/agent_checkpoints.sqlite`: حافظه بین Sessionهای LangGraph.
- `atlas_store/shadow.sqlite`: سبد فرضی، رویدادها، بازدارنده ریسک و زنجیره هش.
- `atlas_store/live_trade_tapes/*.jsonl`: معاملات **واقعاً منتشرشده** روی WebSocket.

**محدودیت ذخیره:** «همه داده‌های ممکن» یعنی همه داده‌هایی که API عمومی واقعاً در دسترس قرار دهد، نه داده‌هایی که هرگز توسط والکس منتشر نشده‌اند؛ شکاف‌ها به‌صراحت ثبت می‌شوند. برای آرشیو کامل رویدادهای Tick لازم است جمع‌آوری زنده از زمان شروع فعال باشد؛ API عمومی به‌خودی‌خود تضمین نمی‌کند تمام رویدادهای قدیمی قابل بازیابی‌اند.

## استراتژی‌های تکنیکال

`atlas_signals.py` ده‌ها خانواده و ترکیب قاعده‌مند دارد: SMA/EMA، MACD، Ichimoku، RSI، Fibonacci، Bollinger، Donchian، VWAP، OBV، ATR، Stochastic، Williams %R، CCI، MFI، ADX، Volume breakout و Momentum. اندیکاتورها فقط از داده تا کندل جاری استفاده می‌کنند؛ Ichimoku بدون نشت از Span آینده، و Fibonacci از Swing پیشین ساخته می‌شود. در بک‌تست، فرض ورود در **Open واقعی کندل بعد** است (نه Close جاری). قیمت فرضی جدید تولید نمی‌شود؛ اما Fill و کارمزد همچنان **شبیه‌سازی فرضی** محسوب می‌شوند.

```bash
python -m wallex_bot.atlas_cli benchmark
```

## دو مدل عمیق مبتنی بر داده واقعی

- iTransformer-inspired inverted-variable attention، حدود ۵٫۴ میلیون پارامتر
- PatchTST-inspired patch-level attention، حدود ۵٫۴ میلیون پارامتر

هر دو از صفر روی پنجره‌های واقعی Wallex آموزش می‌بینند؛ خروجی بازده احتمالاتی q10/q50/q90 برای سه کندل آینده، معماری ۵ بلوک Transformer، ۲۵۶ بعد نهفته، ۸ Attention Head و تابع Quantile pinball دارند. اینها بازپیاده‌سازی الهام‌گرفته از مقاله‌اند، نه وزن رسمی pretrained نویسندگان. پنجره‌هایی که Feature آنها ناقص است حذف می‌شوند؛ هر جفت Train/Validation از نظر زمانی جدا و label boundary purged است. GPU به‌صورت خودکار انتخاب می‌شود و روی دستگاه فاقد CUDA به CPU برمی‌گردد.

```bash
python -m wallex_bot.atlas_cli train-deep
```

آموزش مدل عمیق با داده چندروزه تضمین‌کننده سود نیست. هیچ ادعای SOTA یا عملکرد تجاری برای مدل آموزش‌ندیده وجود ندارد. مدل سنگینِ دارای عملکرد بد از مدل ساده سودمندتر نیست.

## اخبار واقعی و کنترل Leak

جمع‌آوری خبر از GDELT DOC 2.0 با تاریخ انتشار و URL واقعی:

```bash
python -m wallex_bot.atlas_cli news
```

`available_at = max(published_at, first_observed_at)`؛ یعنی خبر دانلودشده امروز **نمی‌تواند به گذشته تزریق شود** حتی اگر تاریخ انتشارش قدیمی باشد. `FinBERT` برای تحلیل متن مالی کد اختیاری دارد؛ **مجوز وزن‌های مدل را قبل از استفاده در رقابت دارای جایزه بررسی کنید**. نصب اختیاری با `pip install transformers` و اجرا با:

```bash
python -m wallex_bot.atlas_cli finbert
```

## دریافت زنده داده‌های واقعی WebSocket

```bash
python -m wallex_bot.atlas_cli capture-live
```

این دستور به `wss://api.wallex.ir/ws` وصل می‌شود، روی بازارهای TMN دارای بیشترین حجم واقعی Subscribe می‌کند، و پیام‌های واقعی `@trade` و زمان دریافتشان را نگه می‌دارد. هیچ معامله فرضی در فایل Trade Tape ساخته نمی‌شود. راه‌اندازی دوباره پس از وقفه، پیام گمشده را **حدس نمی‌زند**.

## ایجنت چندتخصصی و حافظه پایدار

```bash
python -m wallex_bot.atlas_cli agent-cycle
```

گردش LangGraph: Market Data -> Technical Analyst -> News PIT -> Deep Predictor -> Risk Manager -> Paper Executor. `SqliteSaver` حالت اجرای بین Sessionها را ذخیره می‌کند و `shadow.sqlite` وضعیت سبد و جزئیات تصمیم را نگه می‌دارد. `MemorySaver` فقط حالت درون‌پردازشی است و جایگزین حافظه پایدار نمی‌شود.

```bash
python -m wallex_bot.atlas_cli shadow-cycle
python -m wallex_bot.atlas_cli watch
```

`watch` چرخه‌های Shadow را در **فرایند در حال اجرای خود شما** تا سقف ۴۸ ساعت ادامه می‌دهد و در پایان تلاش می‌کند موقعیت‌های فرضی را فقط بر مبنای Bid واقعی مشاهده‌شده ببندد؛ اگر داده تازه موجود نباشد، مقدار/فروش ساختگی ثبت نمی‌کند. این هیچ سفارشی در والکس ثبت نمی‌کند. آخرین نسخه مدل از روی Validation Pinball انتخاب می‌شود؛ امتیاز بالای مدل نباید جایگزین کارایی مالی مستقل شود.

## امنیت و محدودیت‌های مسابقه

- هیچ دستور برداشت یا ارسال سفارش در گردش Atlas وجود ندارد. کلید با مجوز برداشت باید با کلیدی محدود جایگزین شود.
- تمام بازارهای عمومی برای **تحقیق** قابل کشف‌اند؛ بازارهای **مجاز معامله مسابقه** باید علاوه بر `is_spot` با محدودیت حساب پکیج و اعلام رسمی برگزارکننده تطبیق داده شوند.
- API `GET /v1/prop/packages/{id}` محدودیت‌های پکیج را می‌دهد؛ بدون ID معتبر نباید به مدل اجازه سفارش داد. این ID در خروجی `/sub-accounts` کاربر دیده نشده و از `clientId` قابل استنتاج امن نیست.
- مبلغ ۵٬۰۰۰٬۰۰۰ تومان مربوط به حساب تیم را به عنوان بودجه فرضی در Shadow به کار می‌بریم؛ این به معنی اتصال به حساب واقعی یا برداشت از آن نیست.
- کارمزد پیش‌فرض `0.001` **فقط فرض پژوهشی** است؛ هزینه واقعی باید از وضعیت حساب/سفارش با منبع قابل بررسی احراز شود.
- هیچ معاملات صوری، self-trading، wash trading یا عملیات تیمی هماهنگ طراحی نشده است.
- برای اتمام رسمی چالش باید **در حساب واقعی** همه کوین‌ها به تومان تبدیل شوند؛ Shadow فقط پایانِ فرضی را ثبت می‌کند.
